# 数据库

## MS_Description 生成器吃掉首行 `<see>`

- **现象**：列描述出现「（指向 ）」「（见 ）」这种空洞残留
- **根因**：`db/gen-descriptions.ps1` 生成时**只取 XML 注释 summary 首行**，且首行里的 `<see>` 标签会被解析清空，留下空括号
- **解法**：约定——首行必须是**简洁名词短语**（不带表名重复、不带句号）；引用其它表/列一律写进 `<para>` 段落（不进库，只进代码文档）
- **预防**：格式统一写死：字典引用「字典 xxx」、唯一约束「（唯一，仅约束未删除记录）」、枚举含义「0xx 1xx」

## 编辑 summary 丢闭合标签，列描述串位

- **现象**：某列的描述跑到下一列去了，从中间某列开始全部错一行
- **根因**：手工编辑实体注释时丢了 `</summary>` 闭合行，生成器按标签层级解析错位，之后全错
- **解法**：补回闭合标签重新生成
- **预防**：改完实体注释**必跑 `dotnet build`**，CS1570 警告（XML 注释格式错误）能兜底抓出这类问题

## ht_app 无 DDL 权限（这是特性不是坑）

- **现象**：应用账号执行描述/索引脚本报权限不足
- **根因**：`ht_app` 是最小权限账号（2026-09-29 脚本刻意收紧），本就不该有 DDL
- **解法**：DDL 走本机默认实例的管理通道：`sqlcmd -S . -d DB_ERP -E -f 65001`（Windows 集成认证 + UTF-8 代码页防中文乱码）
- **预防**：脚本分两类管理——`sql/`（权限节点、DDL）用管理通道；业务数据走应用。所有脚本写成**幂等可重放**

## 唯一索引必须带软删除过滤

- **现象**：供应商删除重建同编码，报唯一约束冲突
- **根因**：唯一索引把软删除的行也算进去了
- **解法**：过滤索引 `WHERE IsDeleted = 0`（`sql/2026-09-28-fix-unique-indexes-soft-delete.sql`），描述统一标注「（唯一，仅约束未删除记录）」
- **预防**：新表建唯一索引时三问：软删除过滤了吗？描述标注了吗？ArchTests/约定检查覆盖了吗？
