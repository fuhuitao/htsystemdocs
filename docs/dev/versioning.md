# 版本号规范

## 规则：`v年.周.周内修订`（CalVer）

```
v2026.41.0
  │  │  └─ 周内修订号：本周第 1 次发布为 0，同周热修依次 +1
  │  └──── ISO 周号（周一为一周之始，周一 01-04 到周日 01-10 为第 1 周）
  └─────── 年份
```

**为什么不用 SemVer（v1.2.3）**：本系统约定「平均每周一个小版本」，SemVer 的次版本号会无限膨胀（v0.41.0），而且从号上看不出发布时间；CalVer 让版本号自带时间线——看号就知道哪周发的，更新日志、git tag、部署记录三处零成本对齐。

## 每周发版 SOP

### 1. 确定本周版本号

```powershell
# 取当前 ISO 周号
[System.Globalization.ISOWeek]::GetWeekOfYear([DateTime]::Now)
```

例如 2026-10-07（周三）返回 `41`，本周版本号即 `v2026.41.0`。

### 2. 写更新日志

在文档站 `blog/` 下新建（文件名 = 发布日期 + 版本号）：

```
blog/2026-10-07-v2026.41.0.md
```

```markdown
---
title: v2026.41.0
tags: [版本发布]
authors: htsystem
---

## 本周概览
…
```

### 3. 主仓库打 tag

```bash
# 提交本周代码后：
git tag -a v2026.41.0 -m "摘要：一句话说明本周主要变更"
git push origin v2026.41.0
```

### 4. 文档站同步提交

文档站仓库同样提交并打上同名 tag（可选，保持两仓库版本对齐）。

## 约定

- 周号用 **ISO 8601**（周一为一周的开始），跨年时周号自然归 1（如 `v2027.1.0`）
- 一周内多次发布（如线上热修）：`v2026.41.1`、`v2026.41.2` 递增
- 某周没有发布就跳过该周号，**不补号**——版本号是时间线索，不是序号
- tag message 写一句话摘要，详细内容放更新日志页
